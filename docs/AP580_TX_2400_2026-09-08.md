# AP580 2.4 kbps：P4 发射端检查

## 后续排查：耳机只有背景音

用户在电脑持续播放音频时反馈耳机只有背景音。检查时 P4 已是 Audio/TX、2400，HPM 已是 Audio/RX、2400；P4 的 UART 原始字节、有效输入帧、发送包及 HPM 有效帧、UART 转发帧均为 0。音频内容尚未进入 P4 的数字语音输入，不能把持续空闲调制视为语音发送成功，也不能据此确定耳机背景音的来源。

P4 增加只读 `RXDIAG` 信息：实际 UART 波特率、RX 引脚电平、高低电平采样次数、UART 帧错误/奇偶错误/溢出事件和 GPIO 复用配置。电平由 UART 任务每轮采样，不改变引脚配置；采样不是逻辑分析仪测量，不能证明不存在任何短脉冲。UART 事件计数来自有界队列，也不是完整的电气波形记录。

新固件已构建并烧录 COM21，应用 SHA-256：`de842f2411fc7424fb906448626b2fdfa6db9fcda9ee0ab14632113b6ba4d1f3`。复位后确认 Text/RX 不发射，再恢复用户检查前的 Audio/TX 状态。超过 20 秒的观察结束时：

优先检查 AP580 输出和物理连线，而非调节 PSK 参数。项目中的 `AP580_CH(3.0) 开发板使用说明.pdf` 第 3–8 页（PDF 第 5–10 页）给出以下检查点：

- 电脑耳机输出接 **J2 / LINE_IN**，**JP2** 选择 **AUD_IN 与 LINE_IN**；J1 / LINE_OUT 用于输出。
- **JP6 第 2 脚 ENC_EN** 为编码使能：接第 1 脚 VCC3.3 或悬空时使能，接第 3 脚 GND 时禁用。
- **JP6 第 4 脚 UART_TX → P4 GPIO33**；第 5 脚 UART_RX ← P4 GPIO32；第 3 或第 6 脚 GND 与 P4 共地。联机时应拆除模块自测用的 UART_TX / UART_RX 短接帽。
- 波特率选择 JP7、JP8 均为 0 时是 115200；模式选择三个 MD 位均为 0 时是正常 2.4 kbps 模式。改动模式或波特率跳线后复位模块。

以上排针编号适用于该说明书中的开发板，其他版本应以实物丝印及对应原理图为准。LINE_IN 未选中可能使模块编码板载麦克风，但仅凭这个问题不能解释 P4 当前连原始 UART 字节都没有的现象。

结束时 P4 保持 Audio/TX 供现场继续排查；启动默认仍为 Text/RX，600/1200/2400 三档代码均保留。本轮 HPM 只读取 STATUS，未修改运行参数、代码或固件。日志、检查脚本和结果位于 `build/ap580-input-debug/` 的 `build.log`、`flash.log`、`p4.log`、`hpm.log`、`observe.py`、`results.json`。真实语音链路仍未通过，需现场核对模块与连线后复测。

## 后续更新：切换到 Audio/TX 后自动持续发送

用户确认默认速率为 **2.4 kbps（2400 bit/s）**，同时要求保留 0.6 / 1.2 kbps。当前已实现：

- 上电保持 Text/RX、BPSK31 / 2000 Hz，不启动发送。
- 切换到 Audio/TX 后自动连续发送，固定 2x8PSK1200F / 2000 Hz，默认输出音量 60。先选 Audio 再选 Tx、先选 Tx 再选 Audio 均支持，无需另外按发送键；仅在 Rx 下选择 Audio 不会发射。
- 进入 Audio/TX 后不再等到第一包 UART 数据才启动调制。无输入时持续发送二进制空闲字节，数据到达后自动接续，输入暂停也不停止调制；不把空闲字节包装成语音帧。
- 移除 GPIO0 按键初始化、扫描和仅供实体按键使用的模式轮换逻辑。LCD/USB 仍可手动切换内容、收发或停止。
- 保留完整的 600 / 1200 / 2400 档协议与播放支持，可用 `APRATE 600`、`APRATE 1200`、`APRATE 2400` 切换。软件档位仍需与 AP580 模块实际档位一致；复位后回到构建配置的默认档位，当前为 2400。

验证：三档现有封包、PSK 回环、UART 播放测试全部通过。新增三档连续流测试覆盖“空输入启动 → 第一批语音 → 数秒空闲 → 第二批语音 → 空闲”，确认发送持续活跃、所有真实帧逐字节一致、没有产生假语音帧或 CRC 错误。

## 结论与范围

本次链路为电脑音频 → AP580 → P4 UART1 → P4 ES8311 → 音频线 → HPM6750 → AP580 → 耳机。

**P4 到 HPM 的 PSK 音频发射已通过一个已知文本窗口检查；完整语音链路尚未通过。** 两轮语音测量中，P4 UART 原始输入字节、有效语音帧、调制器消费包数均为 0。电脑持续播放是用户确认的状态，不能据此认定 AP580 已经输出串口数据。

仅修改、构建及烧录 P4。HPM6750 只通过 COM23 调整运行参数，未修改代码或烧录；检查时 HPM 工作区干净，HEAD 为 `c84c683eb9e282c3ff7c819623f7a4f1d4078abb`。

## P4 固件改动

- `sdkconfig` 和 `sdkconfig.defaults` 启用确认的 GPIO32/33 UART 接线，默认编码档位 2400。
- `RXDIAG` 和网页状态 API 增加 UART 原始字节、同步丢弃、非语音记录及发送包统计。
- `tx_packets/tx_bytes` 表示整个包已被调制器取走，不表示 DAC 已播放完毕；`pending` 仅为待取包队列长度，不含正在调制的包。
- 默认启动为 Text/RX。后续增加切换到 Audio/TX 后自动持续发送，默认 2400 bit/s；无 UART 输入时发送空闲字节，有有效帧时自动接续，600/1200 档仍受支持。以下历史测量保持原记录。

## 输入恢复后的复测

确认 AP580 TX 接 P4 丝印 33、RX 接丝印 32，模块供电且共地；确认模块正常编码模式和 115200 波特率。修改跳线后重启模块，再运行：

```powershell
& C:/Espressif/tools/python/v5.5.5/venv/Scripts/python.exe -u tools/p4_ap580_tx_check.py --seconds 120 --warmup 20 --volume 60 --label live-2400
```

脚本自动设置 P4 Audio/TX、HPM Audio/RX，记录计数差和日志，结束后停止 P4 发射。显式加 `--keep-tx` 可在测量完成后保持发送以便耳机试听。脚本不会构建或烧录任一板。

2.4 kbps 每 22.5 ms 输出一个 16 B UART 帧，约 44.4 帧/s、711 B/s；本项目六帧组一个 PSK 包。检查应看到 P4 原始字节、有效帧和发送包持续增长，HPM 有效帧和 UART 转发持续增长，CRC、队列丢弃等错误计数不增长。

两块板的快照非同时采集，包和 UART 播放存在流水线延迟，脚本容忍 24 帧计数差；这是计数级链路检查，不是逐位载荷比对或声音质量评价。当前 HPM STATUS 未提供 `rxdrop` 时，报告显式列为不可用。最终耳机是否连续可懂仍需要现场试听。
